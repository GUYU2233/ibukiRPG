# 离线本地模型（llama.cpp · GGUF）

从 v0.1.2-rc2 起，Android App 的“离线本地模型”改用 **llama.cpp** 在设备上运行 **GGUF** 格式的模型，替代 v0.1.1 的 MediaPipe（MediaPipe 只能用少数官方打包的 `.task` 模型）。
几乎所有主流开源模型（Qwen、Llama、Gemma、Phi、Mistral、DeepSeek 蒸馏版……）在 Hugging Face 上都有 GGUF 量化版本，导入后即可离线游玩，推理过程不联网。

> 规则、骰子、金币、物品、关系始终由本地引擎决定；本地模型只负责理解输入和写叙事，输出同样经过 Narrative Guard 校验。

## 推荐模型

| 模型 | 量化 | 文件大小 | 建议手机内存 | 说明 |
|---|---|---|---|---|
| **Qwen2.5-1.5B-Instruct** | Q4_K_M | ≈ 1.1 GB | 4 GB 以上 | 首选：中文好、速度快，中端手机每秒约 8～20 token |
| **Qwen2.5-3B-Instruct** | Q4_K_M | ≈ 2.0 GB | 6～8 GB 以上 | 叙事质量明显更好，速度约为 1.5B 的一半 |
| Qwen2.5-0.5B-Instruct | Q4_K_M / Q8_0 | 0.4～0.6 GB | 3 GB | 只适合低端机试用，叙事容易跑偏 |
| Llama-3.2-3B-Instruct / Gemma-2-2B-it | Q4_K_M | 1.6～2.0 GB | 6 GB | 中文不如 Qwen，可作备选 |

- 在 Hugging Face 搜索 “模型名 + GGUF”（例如 `Qwen2.5-1.5B-Instruct-GGUF`），下载文件名带 `q4_k_m` 的 `.gguf` 文件。
- **Q4_K_M** 是速度 / 质量 / 体积的最佳平衡；Q5_K_M、Q8_0 质量略好但更大更慢；不建议在手机上用 F16。
- 7B 及以上模型（Q4 约 4.5 GB）只适合 12 GB 以上内存的旗舰机，且速度很慢。
- 请自行确认模型许可证（Qwen2.5 3B 使用 Qwen Research 许可，其余多为 Apache-2.0 / Llama 社区许可）。

## 使用步骤

1. **设置 → AI 叙事 → 离线本地模型（llama.cpp · GGUF）**。
2. 点 **从本地导入 .gguf 模型**，用系统文件选择器选择下载好的文件。App 会先校验 GGUF 文件头，再复制到应用私有目录（`files/models/model.gguf`），需要与模型同等大小的可用空间。
3. 按需调整参数，点 **保存并应用**。第一次生成时才真正加载模型（大模型需要几秒到十几秒）。

| 参数 | 默认 | 说明 |
|---|---|---|
| 上下文长度 | 2048 | 512～8192 tokens。越长越能“记住”前文，但 KV 缓存占用更多内存、首字更慢；超过模型训练长度时自动截到训练长度 |
| 单次最多生成 | 512 | 每次叙事最多生成的 token 数 |
| CPU 线程 | 自动 | 自动 = CPU 核数 − 2，限制在 2～4；线程过多反而会被小核拖慢 |
| 温度 / Top-P / Top-K | 0.7 / 0.95 / 40 | 采样参数；温度越低越稳定，越高越有创意；另有轻微重复惩罚 |
| GPU 层数 | 0（不可调） | 当前构建只包含 CPU 后端，见下文 |

## 内存需求

加载前 App 用 `ActivityManager.MemoryInfo` 估算：**需要内存 ≈ 模型文件大小 + 上下文 × 约 0.1 MB + 256 MB**。

- 估算超过整机内存的 60%：**拒绝加载**，提示换更小的量化或降低上下文。
- 超过当前可用内存或系统处于低内存状态：**警告**但允许加载（系统可能会关闭其他后台应用）。
- 权重以 **mmap** 方式映射，不占 Java 堆，未用到的页可以被系统按需换出；因此 App **没有开启 `largeHeap`**（它只放大 Java 堆上限，对原生内存没有帮助，反而会让系统更早回收其他应用）。

| 模型 | 上下文 2048 | 上下文 4096 |
|---|---|---|
| 1.5B Q4_K_M（1.1 GB） | ≈ 1.6 GB | ≈ 1.8 GB |
| 3B Q4_K_M（2.0 GB） | ≈ 2.5 GB | ≈ 2.7 GB |

## 稳定性与后台运行

- **前台服务**：生成叙事期间启动一个 `specialUse` 类型的前台服务并显示“本地模型推理中”通知（可在通知上点 **停止**），生成结束立即停止服务。Android 13 以上首次选择本地模型时会请求通知权限；拒绝也能用，只是看不到通知。
- **自动释放**：空闲 5 分钟、系统发出 `onTrimMemory(RUNNING_CRITICAL / COMPLETE)` 或切换到其他 AI 模式时释放模型；下次生成时按原配置自动重新加载。同一时间只有一个模型实例和一个生成任务。
- **取消**：点通知上的“停止”会立即中断生成，已生成的部分作为本回合叙事（仍经 Narrative Guard 校验，不合格时退回模板叙事）；规则结算由引擎完成，不受影响。
- **防崩溃**：加载前校验 GGUF 文件头（魔数、版本、张量数、文件完整性），明显损坏或不是 GGUF 的文件不会交给原生代码；所有原生调用都在后台线程执行。
- **进程被系统回收**：每个回合的事件在提交时就写入 SQLite 存档，进程被杀最多丢失正在进行的那一回合；重新打开后输入框会恢复刚才那句话，再点发送会复用同一个 command_id（引擎按它去重，不会重复执行、不会重新掷骰）。
- **崩溃记录**：Kotlin 未捕获异常写入 `files/crash/last_crash.txt`；Android 11 以上还会在下次启动时读取系统记录的原生崩溃 / ANR / 低内存终止原因。首页会弹出这份记录，可复制后反馈；**不会自动上传**。
- **电池优化（可选）**：少数厂商系统会在后台强行结束前台服务。如果切到后台后生成经常中断，可以在设置页点 **电池优化设置**，在系统页面把 ibukiRPG 设为“不优化 / 允许后台运行”。App 不会强制要求，也不申请直接豁免的权限。

## 函数调用与检索

小模型的函数调用（tool calling）不可靠，本地模型一律不走工具调用：引擎改用**关键词预取**，把与本回合最相关的故事包资料 / 记忆作为 `[RETRIEVED]` 段直接放进提示词（详见 [mcp.md](mcp.md) 的“回退”一节）。在线模型不受影响。

## 聊天模板

优先使用模型 GGUF 元数据里的聊天模板（`llama_chat_apply_template`，支持 ChatML / Qwen、Llama 2/3、Gemma、Phi、Mistral、DeepSeek 等内置格式）；模型没有模板或模板无法识别时，按模板特征退回 Gemma / Llama 3 格式，否则使用 ChatML。

## 技术细节

- llama.cpp 固定为 release **v0.5.0**（源码 tarball 按 SHA256 校验），以 JNI 库 `libibuki_llama.so` 的形式通过 app 模块的 CMake（`android/app/src/main/cpp/`）构建。
- ABI：**arm64-v8a**、**x86_64**（模拟器）。armeabi-v7a（32 位）设备仍可安装和游玩，但本地模型选项显示为不可用。
- CPU 后端以 `GGML_CPU_ALL_VARIANTS` 编译多个变体（armv8.0 / 8.2 dotprod / 8.6 i8mm / 9.x SVE…），运行时按设备 CPU 特性加载最快的一个。
- GPU：当前构建未启用 Vulkan / OpenCL 后端（安卓 GPU 驱动差异大、收益不稳定），“GPU 层数”设置保留但不可调。
- 本地模型通过一个只监听 `127.0.0.1`、随机端口、随机 Bearer token 的 OpenAI 兼容接口（SSE 流式）提供给 Go 引擎，因此与在线模型走同一套提示词与校验路径。

## 从 MediaPipe 迁移

升级到 v0.1.2-rc2 后，旧的 MediaPipe `.task` 模型文件会被删除以释放空间，AI 模式临时切回“离线规则”，设置页会提示重新导入 GGUF 模型；温度 / 上下文 / Top-K / Top-P 设置会保留。
